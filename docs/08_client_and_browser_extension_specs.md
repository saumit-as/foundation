> **FLUTTER MULTI-DEVICE CLIENT & WXT BROWSER EXTENSION SPECIFICATION**

## 1. Flutter Application Specification (`/app_client`)

### 1.1 Target Platforms & Package Dependencies (`pubspec.yaml`)
- **Targets:** Android (API 29+), Linux Desktop (GTK), Windows Desktop.
- **Core Packages:**
  - State & DI: `flutter_riverpod`, `riverpod_annotation`
  - Offline SQLite: `drift`, `sqlite3_flutter_libs`
  - Networking & Tunnel Auth: `dio`, `web_socket_channel`, `connectivity_plus`
  - Security & Zero-Typing QR Pairing: `flutter_secure_storage`, `mobile_scanner` (1-scan QR code onboarding from `app.cli register-device --qr`)
  - OS Share Receiver: `receive_sharing_intent` (Android Share Sheet for Reels, URLs, PDFs, images)
  - Camera & Multi-Page Book Burst Scanner: `image_picker`, `cunning_document_scanner` (auto edge-detection, perspective crop & multi-page burst scanning)
  - Notifications & Background: `flutter_local_notifications`, `workmanager`
  - UUID Generation: `uuid` (`Uuid().v7()` for time-ordered primary keys)

### 1.2 Six Core UI Screens (`app_client/lib/features/`)

1. **1-Scan QR Device Onboarding (`features/onboarding/`):**
   - Shown on first launch if `flutter_secure_storage` has no credentials.
   - Scans the ASCII QR code printed by `uv run python -m app.cli register-device --qr` (or accepts pasted JSON on Desktop), stores `CF-Access-Client-Id`, `CF-Access-Client-Secret`, `Bearer` key, and `ntfy` token in `flutter_secure_storage`, and immediately runs initial delta sync.

2. **Fast Scratchpad, Active Book Session & Marginalia Stream (`features/scratchpad/`):**
   - Opens directly with the cursor focused in the quick-capture composer (0-tap thought entry).
   - **Sticky Book / Reading Session Banner:** One tap to pin an active book (e.g., *"📖 Active Book: Crafting Interpreters"*). While active, tapping the **Burst Book Scan** camera button launches multi-page document scanning (`page_order = 0, 1, 2...`) and automatically tags and titles every scan under that book session.
   - **Voice Memo Distillation Card:** For `audio_memo` items, displays the bulleted thought summary + action items (`voiceDistillationJson`) right above the audio waveform player, with the 100% verbatim `transcriptText` collapsible below.
   - **Strict Immutability + Append-Only Marginalia:** Original `rawText` is never altered; users can tap **"Reply / Add Follow-up"** on any capture card to append timestamped `LocalCaptureAnnotations` notes below the original thought, while extracted OCR/transcripts/`autoTags` sit in the collapsible *"Extracted Context"* drawer.

3. **AI Sparks, Idea Graph & Vault Export (`features/sparks/`):**
   - Split-pane view on Desktop (tabbed sheet on Mobile):
     - **Left/Primary Pane:** The synthesized `LocalAiSparks` Markdown document generated by `gpt-6-luna`.
     - **Right/Bottom Drawer ("Source Captures"):** Interactive cards showing the exact immutable `user_raw` notes, Reels, PDFs, and book scans that sparked the document.
   - **"Promote / Export to Markdown Vault" Button:** One-click export (`GET /api/v1/sparks/{id}/export.md`) to a local Obsidian/Markdown directory with YAML frontmatter and `[[wiki-links]]`.

4. **Multimodal Semantic Search & "Ask Memoria" RAG (`features/search/`):**
   - Instant local SQLite `LIKE` / tag filtering while offline.
   - **Search Mode (`POST /api/v1/search`):** Queries `EmbeddingGemma 2` `768d` + BM25 RRF and badges whether the match came from a video frame, audio transcript, book/PDF page, or note text. Supports multi-selecting results and clicking **"✨ Synthesize Selected into Spark"** (`POST /api/v1/sparks/synthesize`).
   - **"Ask Memoria" Mode (`POST /api/v1/search/ask`):** Conversational synthesis mode that answers questions across your entire personal context with inline clickable `[capture_id]` citations and a 1-tap **"Save Answer as Spark"** button.

5. **Morning / Evening Triage Deck (`features/triage/`):**
   - Fast card-swipe deck on Mobile / keyboard-driven (`J`/`K`, `P` to Pin to Project, `E` to Archive, `X` to Dismiss) on Desktop for reviewing unreviewed captures and unread `ai_sparks` from the last 48 hours.
   - Feeds explicit positive/negative relevance signals back into the nightly `persona.json` reflection job.

6. **OS Share Sheet Receiver Modal (`features/share_receiver/`):**
   - Intercepts shared Instagram Reels, YouTube links (including `?t=` timestamps), PDFs, web articles, or images from any Android app via `ReceiveSharingIntent.instance.getMediaStream()`.
   - Shows a compact bottom-sheet overlay allowing the user to add an optional 1-line thought or `#tag` and hit **Save** (writes to Drift SQLite outbox in `<15ms` and dismisses immediately back to the previous app).

### 1.3 Offline Outbox Sync Engine (`app_client/lib/data/sync/outbox_flusher.dart`)
```dart
// Triggered on:
// 1. Every new local capture insert
// 2. Connectivity change (offline -> online)
// 3. Periodic 5-minute timer / Android WorkManager wakeup
```
1. Query `OutboxSyncQueue` ordered by `seqId ASC` where `nextRetryAt IS NULL OR nextRetryAt <= NOW()`.
2. If `operation == 'CREATE_CAPTURE'`, send `POST /api/v1/capture` (or `/api/v1/capture/batch`).
3. If `operation == 'UPLOAD_MEDIA'`, stream file via `POST /api/v1/capture/{id}/media`.
4. On `HTTP 202` / `201`, delete row from `OutboxSyncQueue` and update `LocalCaptures.syncStatus = 'SYNCED'`.
5. Immediately call `GET /api/v1/sync/delta?since_version=<last_version>` to pull down any completed server transcriptions, OCR, or `ai_sparks`.

## 2. WXT Browser Capture Extension Specification (`/extension`)

### 2.1 Architecture & Permissions (`wxt.config.ts`)
- **Purpose:** Fast capture companion + authenticated browser rescue helper (per architectural requirement #3). Does not bloat the browser with heavy local ML models.
- **Manifest V3 Permissions:** `activeTab`, `contextMenus`, `storage`, `scripting`, `alarms`, `cookies` (optional opt-in for `yt-dlp` cookie sync on `instagram.com`, `youtube.com`, `x.com`).
- **Keyboard Shortcuts:**
  - `Alt+Shift+S`: Open Quick Scratchpad Popup with current tab URL + highlighted text pre-filled.
  - `Alt+Shift+C`: Silent 1-keystroke clip of current tab/selection directly to server outbox with toast confirmation.

### 2.2 DOM Fallback Extraction (`entrypoints/content.ts`)
Because some paywalled articles or social feeds block server-side `trafilatura` / `yt-dlp` scraping:
- When the user clips a page from the browser extension, `content.ts` extracts the selected text AND runs `@mozilla/readability` on the live `document.cloneNode(true)` in the browser.
- Sends the cleaned Markdown inside `dom_fallback_markdown` in `POST /api/v1/capture`.
- This guarantees 100% extraction success even on sites where the user is logged in locally in their browser.

### 2.3 Extension Offline Outbox, Cookie Sync & `EXTRACTION_PARTIAL` Rescue (`entrypoints/background.ts`)
- **Offline Outbox:** If the user clips a tab while their laptop is offline, `background.ts` stores the payload in `browser.storage.local` under `pending_outbox[]` and registers a `browser.alarms.create("flush_outbox", { periodInMinutes: 2 })` listener that flushes the queue to `POST /api/v1/capture/batch` as soon as the Cloudflare Tunnel is reachable.
- **Optional `yt-dlp` Cookie Sync:** When enabled in Extension Settings, periodically exports scoped session cookies for `instagram.com`, `youtube.com`, and `x.com` to `POST /api/v1/scraper/cookies` so mobile-shared Reels download without hitting login walls.
- **1-Click "Rescue Queue" Badge:** Polls `GET /api/v1/captures/partial` for any mobile-shared URLs stuck in `EXTRACTION_PARTIAL`, badges the extension icon, and lets the user click **"Rescue All in Background Tab"** to extract the live DOM and push it to `POST /api/v1/captures/{id}/rescue`.
